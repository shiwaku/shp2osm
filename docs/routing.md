# 経路探索エンジンでの検証

変換した `.osm.pbf` を、よく使われている3つの経路探索エンジンに読み込ませて、実際に経路を引けるかを確かめた（2026-10-05）。

## 使ったもの

| エンジン | バージョン | 動かし方 | 試したプロファイル |
|---|---|---|---|
| [OSRM](https://project-osrm.org/) | v26.10.0 | Docker（`ghcr.io/project-osrm/osrm-backend`） | `car`（自動車）、`foot`（徒歩） |
| [Valhalla](https://github.com/valhalla/valhalla) | 3.9.0 | Docker（`ghcr.io/valhalla/valhalla-scripted`） | `auto`（自動車）、`pedestrian`（徒歩） |
| [GraphHopper](https://www.graphhopper.com/) | 11.1 | Java 21（jar） | `car`（自動車）、`foot`（徒歩） |

データは、隣り合う2つの1次メッシュをまとめて変換したもの。

```bash
uv run shp2osm data/N13-24_6440_SHP/N13-24_6440.shp data/N13-24_6441_SHP/N13-24_6441.shp out/N13-24_6440-6441.osm.pbf
```

| | |
|---|---|
| 範囲 | 6440（小樽・余市周辺）＋ 6441（札幌周辺） |
| ノード | 1,549,000 |
| ウェイ | 345,609 |
| `.osm.pbf` | 9.3MB |

## 手順

```bash
scripts/routing/setup.sh out/N13-24_6440-6441.osm.pbf     # 3つのエンジンを準備して起動（約30秒）
uv run scripts/routing/compare.py out/routing/routes.geojson  # 同じ区間を問い合わせて比べる
```

- `setup.sh` は Docker と Java 21 以上を使う。作業ファイルは `out/routing/` にできる
- `compare.py` は区間ごとの距離・時間の表を出し、経路の形を GeoJSON に書き出す。QGIS で `.osm.pbf` と重ねると、エンジンごとの経路の違いが見られる
- 止めるとき：`docker rm -f osrm-car osrm-foot valhalla; kill $(cat out/routing/graphhopper/server.pid)`

## 経路探索に使ったデータ

3つのエンジンとも、`out/N13-24_6440-6441.osm.pbf`（国土数値情報 N13 を変換したもの）だけを読み込んでいる。

| エンジン | 読み込んだファイル |
|---|---|
| GraphHopper | `out/N13-24_6440-6441.osm.pbf`（直接読み込む） |
| OSRM | `out/routing/osrm/{car,foot}/map.osm.pbf`（`setup.sh` がコピーしたもの） |
| Valhalla | `out/routing/valhalla/N13-24_6440-6441.osm.pbf`（`setup.sh` がコピーしたもの） |

- OSRM と Valhalla は Docker の中で動くので、元のファイルを直接読めない。そのため `out/routing/` の下にコピーして読み込ませている。コピーと元ファイルのハッシュ値が一致することを確認した
- 各エンジンは `.osm.pbf` を独自の形式（OSRM は `map.osrm*`、Valhalla は `valhalla_tiles`、GraphHopper は `graph-cache`）に変換して使う。`.osm.pbf` を作り直したら、`setup.sh` を実行し直さないとエンジンには反映されない

## 結果の見方

### 経路を地図で重ねる（QGIS）

`compare.py` が書き出した GeoJSON に、決めた8区間 × 3エンジンの経路（24本）が入っている。今回の結果は [routing/routes.geojson](routing/routes.geojson) に保存した。

1. QGIS に `.osm.pbf` をドラッグ＆ドロップし、`lines` レイヤを選ぶ（背景の道路網）
2. その上に `routes.geojson` を重ねる
3. レイヤのプロパティ →「シンボロジ」→「分類」で、値に `engine` を指定するとエンジンごとに色が分かれる
4. 区間を絞るときは、レイヤを右クリック →「フィルタ」で `"route" = '札幌駅→小樽駅'` のように指定する

属性は `profile`（car / foot）、`route`（区間）、`engine`、`distance_km`、`duration_min`。

### その場で経路を引く（GraphHopper の画面）

`setup.sh` で起動している間は、ブラウザで http://localhost:8989/maps/ を開くと、地図上でクリックして経路を引ける（car と foot を切り替えられる）。

- **経路の線は N13 から計算したもの**だが、**背景の地図はインターネット上の地図タイル**（本物の OpenStreetMap などをもとにしたもの）で、経路の計算には使っていない。背景の道と経路が少しずれたり、背景にある道を経路が通らなかったりするのはこのため
- 読み込んだ範囲（東経140〜142度、北緯42.67〜43.33度）の外では経路は引けない
- OSRM と Valhalla は、この起動方法では地図の画面がない（OSRM は osrm-frontend を追加すれば地図で見られる）

## 結果

### 1. メッシュ境界でもつながっている

N13 は1次メッシュごとにファイルが分かれているが、境界（6440 と 6441 の間は東経141度）にある道路の端点は、両側のファイルで座標が完全に一致していた（143か所すべて）。そのため、2つのファイルを1回で変換すると、同じ座標の点が1つのノードにまとまり、境界でも道路がつながる。

札幌駅→小樽駅（自動車）と小樽駅→小樽運河（徒歩）は境界をまたぐ区間で、3つのエンジンすべてが境界を越える経路を返した。

### 2. 決めた区間の経路

| 手段 | 区間 | OSRM | Valhalla | GraphHopper |
|---|---|---|---|---|
| 自動車 | 札幌駅→小樽駅（境界をまたぐ） | 39.0km・29分 | 38.2km・35分 | 36.0km・27分 |
| 自動車 | 札幌駅→新千歳空港 | 46.0km・37分 | 53.3km・55分 | 47.0km・37分 |
| 自動車 | 札幌駅→定山渓 | 27.6km・22分 | 27.6km・39分 | 27.3km・25分 |
| 自動車 | 小樽駅→余市駅 | 20.6km・16分 | 20.6km・26分 | 20.1km・18分 |
| 自動車 | 大通公園→北大 | 2.0km・3分 | 2.0km・7分 | 2.0km・3分 |
| 徒歩 | 大通公園→北大 | 2.1km・25分 | 2.1km・24分 | 2.1km・25分 |
| 徒歩 | 札幌駅→すすきの | 2.1km・25分 | 2.0km・24分 | 2.1km・25分 |
| 徒歩 | 小樽駅→小樽運河（境界をまたぐ） | 0.9km・11分 | 0.7km・8分 | 0.7km・8分 |

- 札幌駅→小樽駅では、どのエンジンも札樽道（`highway=motorway`）を通った
- **時間は参考程度**。N13 には制限速度（`maxspeed`）がないので、各エンジンが道路の種類から決めた速度で計算している。エンジンによって大きく違う（Valhalla は長め）のはこのため

### 3. ランダムな区間（つながっていない道がないかの確認）

札幌〜小樽の範囲（北緯42.95〜43.20度、東経140.95〜141.50度）の道路上から地点をランダムに選び、3つのエンジンに同じ区間を問い合わせた。

| | 区間数 | 失敗 | 3エンジンの中央値から±10%以内の割合 |
|---|---|---|---|
| 自動車 | 150 | 0（3エンジンとも） | OSRM 98%・Valhalla 74%・GraphHopper 83% |
| 徒歩（3km程度まで） | 100 | 0（3エンジンとも） | OSRM 95%・Valhalla 95%・GraphHopper 98% |

- 全750回の問い合わせで、経路が引けなかったものはなかった。道路網は孤立した部分がほとんどなく、つながっている
- 自動車で距離がばらつくのは、エンジンごとに「速い道」の考え方が違うため（Valhalla は幹線道路を優先して遠回りしがち、GraphHopper は短い道を選びがち）。データの問題ではない
- 最初は範囲内から地点を完全にランダムに選んだが、海（石狩湾）や山の中に落ちた地点は GraphHopper が「近くに道路がない」として失敗した。道路から遠い地点を受け付けるかどうかはエンジンによって違う

## わかった注意点

### 高速道路は両方向に通れる扱いになっている（今は問題ない）

N13 の高速道路は、上り線と下り線をまとめた1本の線になっている（札樽道や道央道を横切って数えると、線は1本だけ）。OSM では「`highway=motorway` は特に書かなくても一方通行」とみなすソフトがあるが、今回の3つのエンジンは `oneway` タグがなければ両方向に通れる扱いにした（往復で同じ経路になった）。

一方通行とみなすソフトで使うと、線を描いた向きの逆には高速道路を走れなくなる。気になる場合は、高速道路に `oneway=no` を明示的に付けるとよい（まだ付けていない）。

### OSRM の徒歩では国道を通れない

OSRM の徒歩プロファイル（`foot.lua`）は、通れる道路の一覧に `highway=trunk` を入れていない。このツールでは国道を `trunk` にしているので、OSRM の徒歩では国道を一切歩けず、国道を渡る・沿って歩く区間で大きく遠回りすることがある（ランダムな区間では、ほかのエンジンの3〜5倍の距離になる例もあった。札幌駅の北側で1.4kmの区間が4.0kmになったなど）。Valhalla と GraphHopper の徒歩は `trunk` を歩ける。

日本の国道には歩道があるのがふつうだが、N13 には歩道の情報がない。OSRM で徒歩の経路を使うなら、`foot.lua` を書き換えて `trunk` を加えるか、国道に `foot=yes` などを付ける対応が必要になる。

### 一方通行・制限速度・右左折禁止はない

N13 にない情報なので、`oneway`、`maxspeed`、右左折禁止（turn restriction のリレーション）は付けていない。経路の形はおおむね妥当だが、実際には一方通行の道を逆に走る経路や、曲がれない交差点で曲がる経路が出ることがある。
